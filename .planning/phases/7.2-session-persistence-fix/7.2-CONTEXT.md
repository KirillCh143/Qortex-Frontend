# Phase 7.2: Session Persistence Fix - Context

**Gathered:** 2026-01-17
**Status:** Ready for research

<vision>
## How This Should Work

Users should be able to work with the application normally - send messages, browse knowledge base - and refresh the page at any time without losing their session. Even if they close the browser and come back later, they should stay logged in.

Right now, the app works perfectly during normal usage (sending/receiving messages), but as soon as you refresh the page, you get kicked to the login screen with a 401 "Invalid user credentials" error in the console. This happens even though we tried increasing the Directus session duration in Phase 7.1 - the problem isn't session timeout, it's something with how tokens are being restored on page refresh.

The authentication flow goes through an nginx proxy (Directus on port 80 → http://directus:8055, n8n on port 81 → http://n8n:5678) which solved CORS issues but might be interfering with cookie/token handling during session restoration.

</vision>

<essential>
## What Must Be Nailed

- **Seamless page refreshes** - User can refresh at any time and stay logged in without interruption
- **Browser session persistence** - User stays logged in even after closing and reopening the browser
- **Complete auth flow through nginx** - Login, token refresh, and session restoration all work correctly through the proxy setup
- **Debug visibility** - Clear logging of what's happening with token refresh during development so we can see exactly where it breaks

</essential>

<boundaries>
## What's Out of Scope

- Remember me checkbox - keep it simple, just make sessions persist
- Multiple device session management - not handling cross-device/browser scenarios
- Auto-logout features - no automatic logout after inactivity periods
- Session activity monitoring - not tracking user activity to extend sessions

</boundaries>

<specifics>
## Specific Ideas

**Infrastructure context:**
- nginx proxy config at USER_IMPUT_FILES/nginx.conf
- Directus proxied: port 80 → http://directus:8055
- n8n proxied: port 81 → http://n8n:5678
- CORS headers handled by nginx (Access-Control-Allow-Credentials: true)
- Frontend runs on http://localhost:5173

**Current behavior:**
- Login works perfectly
- API calls work during normal usage
- Page refresh triggers 401: "Invalid user credentials"
- User gets kicked to login page

**Debug requirements:**
- Want to see token refresh attempts in console
- Need visibility into what's failing during session restoration
- Should be able to trace the auth flow through nginx proxy

</specifics>

<notes>
## Additional Context

This is a critical bug discovered after Phase 7.1. We initially thought it was a session duration issue (15 minutes → 7 days), but the problem persists. The fact that API calls work fine during normal usage but fail specifically on page refresh suggests the issue is with:

1. How tokens are stored (localStorage/cookies)
2. How tokens are restored on app initialization
3. How the nginx proxy passes authentication headers
4. Directus token refresh mechanism

The user needs to be able to trust that their session will persist - this is a blocker for production use.

</notes>
