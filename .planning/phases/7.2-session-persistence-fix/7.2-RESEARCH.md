# Phase 7.2: Session Persistence Fix - Research

**Researched:** 2026-01-17
**Domain:** Directus SDK authentication and session management in React SPAs
**Confidence:** HIGH

<research_summary>
## Summary

Researched the Directus SDK ecosystem for implementing persistent authentication in React single-page applications. The standard approach uses the SDK's built-in authentication composable with custom storage adapters, letting the SDK manage the complete token lifecycle (storage, restoration, automatic refresh).

Key finding: Don't hand-roll token storage or refresh logic. The Directus SDK provides an authentication composable that handles token storage, automatic refresh, and session restoration when properly configured with a custom storage adapter. Manual localStorage management (storing tokens separately, manually calling refresh) conflicts with the SDK's internal auth state and causes page refresh failures.

The "401 Invalid user credentials" on page refresh is a common symptom of manual token management interfering with SDK-managed authentication. The SDK needs to own the entire auth lifecycle to properly restore sessions.

**Primary recommendation:** Use SDK's authentication composable with custom storage adapter implementing get()/set() interface. Let SDK fully manage authentication - no manual token extraction, no manual refresh calls, no separate localStorage keys.
</research_summary>

### Pattern 1: SDK-Managed Authentication with Custom Storage
**What:** Let SDK fully manage auth lifecycle, provide custom storage adapter for persistence
**When to use:** Always for React SPAs requiring session persistence
**Example:**
```typescript
// Source: Directus SDK docs + community best practices
import { createDirectus, rest, authentication } from '@directus/sdk';

// Custom storage implementing get/set interface
class AuthStorage {
  private key = 'directus_auth';

  async get() {
    const data = localStorage.getItem(this.key);
    return data ? JSON.parse(data) : null;
  }

  async set(data: any) {
    if (!data) {
      localStorage.removeItem(this.key);
    } else {
      localStorage.setItem(this.key, JSON.stringify(data));
    }
  }
}

const storage = new AuthStorage();

const client = createDirectus('http://directus.example.com')
  .with(authentication('json', { storage, autoRefresh: true }))
  .with(rest());

export default client;
```

### Pattern 2: Session Restoration on App Initialization
**What:** SDK automatically restores session from storage on initialization
**When to use:** Every React app with authentication
**Example:**
```typescript
// Source: Directus React authentication tutorial
// In AuthContext or root component
useEffect(() => {
  // SDK automatically loads stored tokens on initialization
  // No manual token restoration needed
  client.getToken().then(token => {
    if (token) {
      setIsAuthenticated(true);
    }
  });
}, []);
```

### Pattern 3: Login with SDK Composable
**What:** Use SDK's login() method, SDK handles token storage automatically
**When to use:** All login flows
**Example:**
```typescript
// Source: Directus official React tutorial
const handleLogin = async (email: string, password: string) => {
  try {
    // SDK handles storage via custom adapter
    await client.login(email, password);
    setIsAuthenticated(true);
  } catch (error) {
    console.error('Login failed:', error);
  }
};
```

### Anti-Patterns to Avoid
- **Manual token extraction after login:** Don't access result.access_token and store separately - SDK manages this
- **Separate localStorage keys:** Don't store tokens in separate keys (e.g., 'access_token', 'refresh_token') - use SDK storage adapter
- **Manual refresh calls in interceptors:** Don't create axios/fetch interceptors that manually call refresh - SDK autoRefresh handles this
- **Reading tokens on every request:** Don't read from localStorage before each API call - SDK injects tokens automatically
</architecture_patterns>

<dont_hand_roll>
## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Token refresh logic | Manual setInterval or request interceptors | SDK autoRefresh: true | SDK handles expiration checks, race conditions, refresh timing |
| Token storage | Manual localStorage.setItem/getItem | SDK storage adapter interface | SDK knows when to persist, what to persist, and when to clear |
| Session restoration | Manual token read + validation on mount | SDK automatic restoration | SDK handles token validation, refresh if needed, clearing if invalid |
| 401 error handling | Global axios/fetch interceptors | SDK built-in retry with refresh | SDK knows auth state, can refresh synchronously before retry |
| Logout flow | Manual localStorage.removeItem | SDK logout() method | SDK invalidates refresh token server-side, clears storage |

**Key insight:** Authentication state management is complex - token expiration, refresh timing, concurrent requests, race conditions, storage synchronization. The Directus SDK solves all of these. Manual implementations always miss edge cases that cause "works in dev, breaks in prod" bugs like:
- Page refresh clearing in-memory state but leaving stale localStorage
- Multiple tabs refreshing simultaneously (race condition)
- Token refresh during pending requests (request fails with 401)
- Expired refresh token not detected until request fails
</dont_hand_roll>

<common_pitfalls>
## Common Pitfalls

### Pitfall 1: Manual Token Management Conflicts with SDK
**What goes wrong:** 401 "Invalid user credentials" on page refresh despite valid tokens in localStorage
**Why it happens:** Manual localStorage token storage creates separate state from SDK's internal auth state. On page reload, SDK doesn't know about manually-stored tokens.
**How to avoid:** Never manually store tokens. Use SDK's storage adapter interface. SDK must own the entire auth lifecycle.
**Warning signs:** Login works, API calls work, page refresh logs out user

### Pitfall 2: AutoRefresh Stops After Page Reload
**What goes wrong:** AutoRefresh timer doesn't restart after browser refresh (GitHub issue #22703)
**Why it happens:** SDK sets up autoRefresh timer on client creation, but timer doesn't persist across page loads. If SDK doesn't properly restore session, timer doesn't start.
**How to avoid:** Ensure storage adapter is configured correctly. SDK should detect existing token on initialization and start autoRefresh automatically.
**Warning signs:** First page load works, subsequent reloads fail after token expires

### Pitfall 3: Cookie Mode with Nginx Proxy Configuration Mismatch
**What goes wrong:** Cookies not sent with requests, authentication fails silently
**Why it happens:** CORS_CREDENTIALS=true required on backend, credentials: 'include' required on frontend fetch config, nginx must pass cookies correctly
**How to avoid:** For nginx proxies, ensure Access-Control-Allow-Credentials header is set, and frontend uses same domain or proper CORS setup
**Warning signs:** Login returns 200 but subsequent API calls return 401, no directus_session_token cookie visible in DevTools

### Pitfall 4: Race Conditions with Refresh Tokens
**What goes wrong:** "Invalid user credentials" intermittently on API calls
**Why it happens:** Directus refresh tokens are single-use. If two requests try to refresh simultaneously, second one fails.
**How to avoid:** Use SDK's built-in refresh mechanism (autoRefresh: true), which handles concurrent refresh requests with internal queuing
**Warning signs:** Random 401 errors during heavy usage, works when only one tab/window open

### Pitfall 5: Mixing Authentication Modes
**What goes wrong:** Login uses 'json' mode but refresh expects 'cookie' mode (or vice versa)
**Why it happens:** Inconsistent mode parameter between login and SDK configuration
**How to avoid:** Set authentication mode once in SDK initialization, use same mode for all auth operations
**Warning signs:** Login succeeds but refresh always fails, tokens returned but not used
</common_pitfalls>

<code_examples>
## Code Examples

Verified patterns from official sources:

### Complete SDK Setup with Custom Storage
```typescript
// Source: Directus SDK documentation + React tutorial
// lib/directus.ts
import { createDirectus, rest, authentication } from '@directus/sdk';

class AuthStorage {
  private readonly key = 'directus_auth';

  async get() {
    try {
      const data = localStorage.getItem(this.key);
      return data ? JSON.parse(data) : null;
    } catch (error) {
      console.error('Failed to get auth data:', error);
      return null;
    }
  }

  async set(data: any) {
    try {
      if (!data) {
        localStorage.removeItem(this.key);
      } else {
        localStorage.setItem(this.key, JSON.stringify(data));
      }
    } catch (error) {
      console.error('Failed to set auth data:', error);
    }
  }
}

const client = createDirectus(import.meta.env.VITE_DIRECTUS_URL)
  .with(authentication('json', {
    storage: new AuthStorage(),
    autoRefresh: true
  }))
  .with(rest());

export default client;
```

### React Auth Context with SDK
```typescript
// Source: Directus React authentication tutorial (adapted)
// contexts/AuthContext.tsx
import { createContext, useContext, useState, useEffect, ReactNode } from 'react';
import client from '@/lib/directus';

interface AuthContextType {
  isAuthenticated: boolean;
  login: (email: string, password: string) => Promise<void>;
  logout: () => Promise<void>;
}

const AuthContext = createContext<AuthContextType | undefined>(undefined);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [isAuthenticated, setIsAuthenticated] = useState(false);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    // SDK automatically restores session from storage
    client.getToken()
      .then(token => {
        setIsAuthenticated(!!token);
      })
      .catch(() => {
        setIsAuthenticated(false);
      })
      .finally(() => {
        setIsLoading(false);
      });
  }, []);

  const login = async (email: string, password: string) => {
    // SDK handles token storage via custom adapter
    await client.login(email, password);
    setIsAuthenticated(true);
  };

  const logout = async () => {
    // SDK invalidates refresh token and clears storage
    await client.logout();
    setIsAuthenticated(false);
  };

  if (isLoading) {
    return <div>Loading...</div>;
  }

  return (
    <AuthContext.Provider value={{ isAuthenticated, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

export const useAuth = () => {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth must be used within AuthProvider');
  }
  return context;
};
```

### Nginx Configuration for Directus with Cookies
```nginx
# Source: Community best practices + nginx CORS guides
# Ensure CORS credentials work with nginx proxy

location / {
    proxy_pass http://directus:8055;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # Critical for cookies
    proxy_cookie_path / /;
    proxy_cookie_domain directus:8055 $host;

    # CORS headers (if not set by Directus)
    add_header Access-Control-Allow-Credentials true always;
    add_header Access-Control-Allow-Origin $http_origin always;
}
```

<sota_updates>
## State of the Art (2025-2026)

What's changed recently:

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| Manual token management | SDK authentication composable | SDK v10+ (2023) | SDK now handles full auth lifecycle, manual approach obsolete |
| Cookie mode (legacy) | Session mode | SDK v10.10.0 (2024) | Cookie mode still works for compatibility, session is new name |
| Default memory storage | Custom storage required for persistence | SDK v10+ | Must provide storage adapter for SPA session persistence |
| Manual refresh interceptors | autoRefresh: true | SDK v11+ (2024) | Built-in auto-refresh with race condition handling |

**New tools/patterns to consider:**
- **SDK autoRefresh**: Set to true for automatic token refresh before expiration, eliminates manual refresh logic
- **Storage adapter interface**: Async get()/set() methods allow custom persistence (localStorage, AsyncStorage, IndexedDB)
- **Session mode**: Replaces cookie mode, better semantics for browser-based authentication

**Deprecated/outdated:**
- **Manual localStorage token management**: SDK storage adapter is now the standard
- **Separate access_token/refresh_token keys**: SDK stores complete AuthData object via adapter
- **Manual token refresh in axios/fetch interceptors**: SDK autoRefresh handles this internally
</sota_updates>
