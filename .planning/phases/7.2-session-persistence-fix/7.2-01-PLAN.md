**Current Issue:**
- Login works perfectly
- API calls work during normal usage (sending messages)
- Page refresh triggers 401 "Invalid user credentials"
- User gets kicked to login page

**Root Cause Analysis:**
The auth code manually manages localStorage (`localStorage.setItem('directus_auth', ...)`) while the Directus SDK with `authentication('json')` has its own internal storage management. This creates a conflict:
1. `login()` stores auth data manually in localStorage
2. Directus SDK also stores tokens in its own key format
3. On refresh, SDK can't find tokens in the format it expects
4. Auto-refresh fails → 401 error → logout

**Solution:**
Let the Directus SDK fully manage authentication storage. The SDK's `authentication('json', { credentials: 'include' })` mode handles:
- Automatic token storage in localStorage
- Automatic token restoration on page load
- Automatic token refresh when access_token expires
- Proper header management through nginx proxy

**Tech Context:**
- Directus SDK v20.3.0 with `authentication('json')` mode
- nginx proxy: http://localhost:80 → http://directus:8055
- Frontend: http://localhost:5173
- CORS headers: Access-Control-Allow-Credentials: true
- Session duration: 7-day access tokens, 30-day refresh tokens (configured in Phase 7.1)

**Key Files:**
- `src/contexts/AuthContext.tsx` - Auth state management
- `src/lib/directus.ts` - Directus SDK initialization

2. In `login()`: Remove `localStorage.setItem('directus_auth', ...)` and `localStorage.removeItem('directus_auth')`. Just call `client.login()` and `checkAuth()` - SDK stores tokens automatically.

4. In `checkAuth()`: Remove `localStorage.getItem('directus_auth')` check. Just call `client.request(readMe())` - SDK auto-restores and auto-refreshes tokens from its internal storage.
5. Add console.log in checkAuth() to show when token refresh happens (DEV mode only)
6. Keep the mock mode bypass logic unchanged

**Why this works:**
- SDK manages storage in a consistent format across page loads
- SDK auto-refreshes expired tokens before making requests
- SDK handles credentials properly through nginx proxy with credentials: 'include'
- No manual storage conflicts

**What to avoid:**
- Do NOT manually read/write 'directus_auth' localStorage key - SDK owns this
- Do NOT store tokens in a different format than SDK expects
- Do NOT bypass SDK's automatic refresh mechanism
