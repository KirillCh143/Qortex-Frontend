## Decisions Made

**1. Use explicit localStorage storage handlers**
- Rationale: SDK's default storage wasn't persisting tokens properly
- Implementation: Custom get/set functions with JSON.parse/stringify
- Storage key: 'directus-auth' (consistent, debuggable)

**2. Remove all manual localStorage manipulation**
- Previous approach manually stored tokens in different format than SDK expected
- Created conflicts between manual storage and SDK's internal storage management
- Solution: Let SDK fully own the auth lifecycle through storage handlers

**3. Document authentication flow comprehensively**
- Auth flow is complex (login, refresh, restore, logout, token expiry)
- Future developers need to understand SDK-managed approach
- Added 100+ line JSDoc block explaining lifecycle, storage, nginx proxy, mock mode

## Deviations from Plan

None - plan executed exactly as written.

## Issues Encountered

**Issue 1: Initial attempt with `credentials: 'include'` parameter failed**
- Problem: SDK with `authentication('json', { credentials: 'include' })` didn't store tokens
- Root cause: `credentials: 'include'` is for cookie-based auth, conflicts with JSON token mode
- Solution: Removed credentials parameter, added explicit localStorage handlers instead
- Resolution time: ~15 minutes (caught during checkpoint testing)

**Issue 2: TypeScript errors with storage handler types**
- Problem: Initial storage handlers returned string, SDK expected AuthenticationData object
- Solution: Changed to JSON.parse/stringify for proper serialization
- Resolution time: ~5 minutes

Both issues caught and fixed during Task 1 execution before checkpoint.
