**Issue Context:**
Current download implementation produces URLs like `http://localhost:8080//assets/{id}` (double slash) which returns 404 "Route doesn't exist" errors from Directus. The bug occurs in `files.service.ts` line 27 where `${client.url}/assets/${id}` concatenates a URL that already has a trailing slash.

**Prior work:**
Phase 7.3-02 removed duplicate download requests but didn't catch this URL path bug. The download button triggers the request but fails due to malformed URL.
</context>

  <action>
Fix the downloadFile method (line 25-32) to properly construct the asset URL without double slashes. The issue is that `client.url` includes a trailing slash (e.g., "http://localhost:8080/"), and concatenating `/assets/${id}` creates `//assets/`.

Solution: Remove the leading slash from the path by using `assets/${id}` instead of `/assets/${id}`. This ensures the final URL is correctly formatted as `http://localhost:8080/assets/{id}`.

Change line 27 from:
```typescript
const response = await fetch(`${client.url}/assets/${id}`);
```

To:
```typescript
const response = await fetch(`${client.url}assets/${id}`);
```

AVOID using URL parsing libraries or complex logic - this is a simple string concatenation fix. The client.url already has the trailing slash, so just remove the leading slash from the path.
