  <action>
Create TypeScript types for Portainer containers:
- ContainerStatus type: 'running' | 'stopped' | 'paused'
- ContainerHealth type: 'healthy' | 'unhealthy' | 'none'
- Container interface with: id (string), name (string), status (ContainerStatus), uptime (string), health (ContainerHealth)
- PortainerService interface with: getContainers() => Promise&lt;Container[]&gt;

Create real Portainer service (src/services/portainer/portainer.service.ts):
- Use fetch to call Portainer API: GET /api/endpoints/{endpointId}/docker/containers/json?all=true
- Get Portainer URL from env: VITE_PORTAINER_URL (default: http://localhost:9000)
- Get endpoint ID from env: VITE_PORTAINER_ENDPOINT_ID (default: 2)
- Get API token from env: VITE_PORTAINER_TOKEN
- Transform Portainer response to our Container type
- Map State to ContainerStatus: State.Running → 'running', State.Status === 'paused' → 'paused', else → 'stopped'
- Map Health.Status to ContainerHealth: 'healthy' → 'healthy', 'unhealthy' → 'unhealthy', undefined → 'none'
- Format uptime using State.StartedAt timestamp (calculate duration)
- Handle errors with meaningful messages

Create mock service (src/services/mock/portainer.mock.ts):
- Return sample array of 8-10 containers with varied statuses
- Mix of running (5), stopped (2), paused (1), and different health states
- Realistic container names (nexus-frontend, nexus-directus, nexus-n8n, nexus-postgres, etc.)
- Mock uptime values (2d 14h, 5h 23m, etc.)
- Simulate 100ms delay with setTimeout for realism

Export createRealPortainerService and createMockPortainerService following the pattern from files.service.ts.
