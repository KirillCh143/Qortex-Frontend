# Phase 7.1: Additional fixes - Context

**Gathered:** 2026-01-16
**Status:** Ready for planning

<vision>
## How This Should Work

This phase addresses three critical fixes discovered after Phase 7 (API Integration Layer):

1. **User-specific chat history**: Currently all users see the same chat regardless of who's logged in. Each user should have their own private chat with unique history stored in Directus database (tied to user ID). Chat history should persist across devices and sessions.

2. **Persistent auth sessions**: Directus sessions expire too quickly (every 5 minutes or less), forcing frequent re-logins. Sessions should remain active until the user manually clicks the 'Logout' button. This will be achieved by extending the Directus session duration configuration.

3. **ReactQueryDevtools toggle**: Add an environment variable (like VITE_USE_MOCK_DATA) to control ReactQueryDevtools visibility, allowing clean production builds without dev tools.

Users should experience clear feedback when these fixes are working - loading states when fetching chat history from Directus, and indication that their chat is tied to their account.

</vision>

<essential>
## What Must Be Nailed

- **User-specific chat history** - This is THE critical fix. Each user must see only their own chat messages, stored in Directus and tied to their user ID. This is a fundamental functional issue that blocks everything else.

</essential>

<boundaries>
## What's Out of Scope

- Chat UI improvements - Not changing how chat looks or adding new chat features; just fixing the storage mechanism
- Chat history migration - Not migrating existing localStorage chat data to Directus; start fresh with new per-user storage
- Performance optimization - Not optimizing chat loading speed or message pagination; that's Phase 8 territory
- Advanced auth features - Not adding password reset, 2FA, or remember-me checkbox; just fixing session duration

</boundaries>

<specifics>
## Specific Ideas

- Chat history stored in Directus database (not localStorage)
- Show loading states when fetching chat history from Directus
- Maybe display a message/indicator that chat is tied to the user's account
- Extend Directus session duration via configuration (simpler than auto-refresh)
- ReactQueryDevtools controlled by environment variable similar to VITE_USE_MOCK_DATA pattern

</specifics>

<notes>
## Additional Context

Priority ranking:
1. User-specific chat history (critical)
2. Persistent auth sessions (important UX fix)
3. ReactQueryDevtools toggle (nice to have for production)

User wants clear feedback that these fixes are working - the experience should feel transparent and reliable. Users shouldn't be surprised when their chat history follows them across sessions or when they stay logged in.

</notes>
