**Status:** ✅ SHIPPED 2026-02-01

**Total Plans:** 47

## Overview

This roadmap took the RAG Agent Frontend from initial project setup through to a production-ready chat interface. Starting with foundational tooling and layout, building authentication and chat interfaces using mock data for UI approval, then integrating real APIs with Directus and n8n. The journey emphasized mock-first development to validate UX before backend complexity, culminating in a polished employee documentation search experience with role-based access control.

## Milestone Summary

**Decimal Phases:**

- Phase 7.1: Additional fixes (inserted after Phase 7 for urgent chat history fix)
- Phase 7.2: Session Persistence Fix (inserted after Phase 7.1 for 401 error fix)
- Phase 7.3: Directory Structure Integration (inserted after Phase 7.2 for folder navigation)
- Phase 7.4: Fix files download (inserted after Phase 7.3 for auth token fix)
- Phase 7.5: Login page design overhaul (inserted after Phase 7.4 for design alignment)

**Key Decisions:**

- Mock-first development (Rationale: Approve UI visually before backend complexity)
- Code quality tooling upfront (Rationale: Consistent code from day one)
- Directus for chat history (Rationale: User-scoped storage over localStorage)
- SDK-managed auth storage (Rationale: Fix session persistence bugs)
- Purple theme #8466e4 (Rationale: Modern professional branding)
- Env-based API config (Rationale: Simpler than frontend settings page)
- Client-side simulated streaming (Rationale: n8n doesn't support token streaming)
- Three-tier RBAC (Rationale: Clean permission model with frontend_role field)
- Silent redirect for unauthorized (Rationale: Seamless UX per role)

**Issues Resolved:**

- 401 errors on page refresh (Phase 7.2 — explicit localStorage handlers)
- File download authentication failures (Phase 7.4 — Bearer token pattern)
- Markdown rendering inconsistencies (Phase 8 — custom ReactMarkdown renderers)
- Dialog/Select transparent backgrounds (Phase 8 — explicit bg-white)
- Tailwind CSS variable caching issues (Phase 7.5 — hardcoded hex values)

**Issues Deferred:**

- Mobile optimization (desktop-first approach sufficient for v1.0)
- User management UI (admin uses Directus directly)
- Advanced AI features (current RAG + LLM covers needs)

**Technical Debt Incurred:**

- Client-side simulated streaming (true streaming requires n8n changes)
- Hardcoded hex values in some components (Tailwind variable workaround)
- Selection checkboxes in Knowledge Base are visual-only (no state management)
